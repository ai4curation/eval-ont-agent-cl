## Rationale for the conservative approach

The original PR description ("such as `oboInOwl:hasDbXref`, `IAO:0000115`, `oboInOwl:hasExactSynonym`, etc. that already have a label defined in the `merged_import` module") states the criterion rather than enumerating every removal. I applied the criterion strictly: a label is removed only if the same predicate–subject pair already carries an `rdfs:label` in `merged_import.owl`. This avoids accidentally dropping CL-only labels for properties that happen to be declared (but not labeled) upstream — e.g., `IAO_0000028` is declared in `merged_import` but has no `rdfs:label` there, so its `"symbol"` label was kept.
