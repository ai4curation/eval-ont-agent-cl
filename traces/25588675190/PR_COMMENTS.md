## Summary

This PR addresses issue #3224 by excluding `skos:prefLabel` annotation properties from MBAO imports to prevent editing workflow conflicts in Protégé.

## Changes Made

Modified `src/ontology/cl-odk.yaml` to add annotation property exclusions for the MBAO import:

```yaml
- id: mbao
  mirror_from: https://raw.githubusercontent.com/brain-bican/mouse_brain_atlas_ontology/main/mbao-base.owl
  annotation_property_exclusions:
    - skos:prefLabel
```

## Rationale

The issue reported that when attempting to obsolete terms in Protégé, modifications were occurring in `merged_import.owl` instead of `cl-edit.owl`. Investigation revealed that:

1. Terms from MBAO were being imported with `skos:prefLabel` annotations
2. These `skos:prefLabel` values were typically identical to the existing `rdfs:label` values, making them duplicative
3. The presence of these imported annotations was causing Protégé to modify the import file rather than the edit file

By excluding `skos:prefLabel` from MBAO imports, we:
- Prevent the duplicative annotations from being imported
- Ensure that Protégé edits occur in `cl-edit.owl` as expected
- Maintain all necessary label information via existing `rdfs:label` annotations

## Validation

Confirmed that `skos:prefLabel` annotations were present in `merged_import.owl` before this change:
- Found `<http://www.w3.org/2004/02/skos/core#prefLabel>` declarations and assertions for multiple CL terms
- These annotations originated from the MBAO import

## Next Steps

After this PR is merged, the MBAO import will need to be regenerated using the ODK to apply the new exclusion filter and remove existing `skos:prefLabel` annotations from `merged_import.owl`.
