## Summary

This PR addresses issue #3224 by excluding `skos:prefLabel` annotations from MBAO imports, which were interfering with the standard term obsoleting workflow in Protégé.

## Changes

Modified `src/ontology/cl-odk.yaml` to add an explicit `annotation_properties` configuration for the MBAO import that excludes `skos:prefLabel`.

**Before:**
```yaml
- id: mbao
  mirror_from: https://raw.githubusercontent.com/brain-bican/mouse_brain_atlas_ontology/main/mbao-base.owl
```

**After:**
```yaml
- id: mbao
  mirror_from: https://raw.githubusercontent.com/brain-bican/mouse_brain_atlas_ontology/main/mbao-base.owl
  annotation_properties:
    - rdfs:label
    - IAO:0000115
    - oboInOwl:is_metadata_tag
    - OMO:0002000
```

## Rationale

The issue reporter discovered that when attempting to obsolete terms in Protégé, modifications were occurring in `merged_import.owl` instead of `cl-edit.owl` as expected. This was caused by `skos:prefLabel` annotations being imported from MBAO, which override the standard editing behavior.

Since `skos:prefLabel` values from MBAO are typically identical to `rdfs:label` (which is already imported), excluding them provides no loss of information while fixing the editing workflow interference.

## Impact

- **Editing workflow**: Term obsoleting in Protégé will now correctly modify `cl-edit.owl` only
- **Data preservation**: All essential annotations (label, definition, metadata tags) continue to be imported from MBAO
- **No breaking changes**: This only affects future import builds; existing terms are not modified by this configuration change

## Testing

After the next import refresh, editors should verify that:

- [ ] Essential MBAO term information (labels, definitions) is still imported correctly
- [ ] `skos:prefLabel` no longer appears in `merged_import.owl` for MBAO terms
